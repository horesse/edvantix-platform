# EDX-031 · Собственный бот школы

## Контекст

Решение № 1 зонтика — один бот платформы: школа ничего не настраивает, секретов в БД нет.
Цена: родитель видит «Edvantix», а не «Школа «Лингва»». Часть школ попросит свой бренд —
как в «Мой Класс», где школа вставляет токен своего бота. Делать **только по запросу
первых клиентов**; до этого — не блокер.

Главное препятствие — хранение токена бота школы. Это секрет, и класть его в
`TenantSettings` открытым текстом нельзя. Шифрование «at rest» (Data Protection с ключами
вне БД) — общая инфраструктура, а значит `src/BuildingBlocks` и правило 4 (нужно
согласование). Тот же механизм понадобится онлайн-оплате (мерчант-ключи, пункт 1.1
[[Дорожная карта развития|дорожной карты]]) — делать один раз.

## Что сделать

- [ ] **BuildingBlocks (по согласованию):** `IProtectedSecretStore` / value-converter
      EF для шифрованных колонок на Data Protection; ключи — в Redis/файловой системе
      вне БД, как для JWT.
- [ ] `TenantTelegramBot` (тенант-изолирована): `BotTokenEncrypted`, `BotUsername`,
      `WebhookSecret`, `IsActive`, `VerifiedAtUtc`. `PUT /school/settings/telegram-bot`
      (`SchoolSettings.Manage`): сохранить токен → `getMe` для проверки → `setWebhook` на
      `/api/v1/telegram/webhook/{tenantId}`.
- [ ] `ITelegramBotClient` — фабрика по тенанту: свой бот, если есть и активен, иначе
      платформенный. `SendTelegramMessageJob` получает тенант и выбирает клиента.
- [ ] Вебхук с сегментом тенанта; секрет сверяется с секретом бота этого тенанта.
      Привязки `TelegramLink` остаются прежними — `chat_id` у пользователя один и тот же
      для любого бота? **Нет**: `chat_id` приватного чата равен `user_id`, поэтому
      совпадает, но пользователь должен нажать «Start» у нового бота, иначе бот писать не
      может. Переход школы на свой бот → все привязки школы деактивировать с причиной
      `BotChanged`, разослать через **старый** бот последнее сообщение со ссылкой на новый.
- [ ] Dashboard `/school/settings`: блок «Свой Telegram-бот» — инструкция в три шага
      (BotFather → токен → вставить), проверка, статус, «Вернуться к боту Edvantix».
- [ ] Документация модуля, карта экранов, `deploy/` (ничего нового — токены в БД).

## Зависимости

- Блокируется: [[EDX-022 Клиент бота и приём обновлений Telegram]]; фактически — решение
  по шифрованию секретов в `BuildingBlocks`.
- Связано: [[EDX-008 API-ключи в Identity]] (хэшируемые, не шифруемые — другой случай),
  онлайн-оплата из дорожной карты (тот же секрет-стор).

## Проверка

- Токен не читается из БД в открытом виде (проверка колонки).
- Школа со своим ботом: привязка, доставка, `/stop` работают через её бот; школа без
  своего — через платформенный, в той же инсталляции одновременно.
- Смена бота → старые привязки деактивированы, родители получили ссылку на новый.
