# EDX-027 · Подключение Telegram для людей без учётной записи

## Контекст

У большинства родителей и части учеников учётной записи нет — они существуют только
записями [[People]] с e-mail и телефоном, и уведомления им уходят письмом. Именно они
главная аудитория Telegram-канала (решение № 5 зонтика). Два пути к ним: менеджер выдаёт
ссылку с карточки, и ссылка автоматически попадает в футер каждого письма-уведомления.
Эндпоинт `POST /notifications/telegram/invites` и статус — из [[EDX-023 Привязка получателя к Telegram]].

## Что сделать

**Карточки People** (`pages/people/student-detail.tsx`, `guardian-detail.tsx`, `teacher-detail.tsx`)
- [ ] В блоке контактов — строка **«Telegram»**: «Подключён @username» / «Не подключён» /
      «Отключён: бот заблокирован». Данные — `GET /notifications/telegram/status?recipient=…`
      (одним запросом вместе с карточкой не получится — модули разные; кэшировать по id).
- [ ] Кнопка **«Ссылка для подключения»** → `POST /notifications/telegram/invites` → диалог:
      ссылка с кнопкой «Скопировать», QR-код (показать родителю с экрана на встрече),
      готовый текст сообщения «Здравствуйте! Подключите уведомления школы «…» в Telegram:
      {ссылка}» с кнопкой «Скопировать текст» — менеджер вставляет в WhatsApp/SMS.
      Подпись «Действует 30 дней. Повторный выпуск отменяет предыдущую ссылку».
- [ ] Нет e-mail и нет учётки → кнопка неактивна с подсказкой «Укажите e-mail —
      он нужен, чтобы адресовать уведомления» (ограничение решения № 4).
- [ ] На карточке ученика — то же для каждого представителя в блоке «Представители»
      (иконка-статус + действие в меню строки), чтобы не ходить по карточкам.

**Списки**
- [ ] `/students`, `/guardians`: фильтр «Telegram: подключён / нет» — менеджеру нужно
      видеть, кого ещё уговаривать. Backend: `GET /notifications/telegram/links?recipients=…`
      батчем по видимой странице (не N запросов), либо колонка-иконка без фильтра, если
      батч окажется дорогим. Решить при реализации, зафиксировать в документации модуля.

**Футер писем** (backend, `Modules.Notifications`)
- [ ] `EmailNotificationChannel` и `NotificationDigestJob`: если у получателя нет активной
      привязки — дописывать в конец письма «Получать уведомления в Telegram → {ссылка}».
      Ссылка — действующий токен получателя (`IssueTokenAsync` возвращает текущий, если
      он ещё жив; выпускать новый на каждое письмо нельзя — аннулировал бы ссылку, которую
      менеджер только что отправил). Письма Billing и Identity не трогать.
- [ ] Для получателей с учёткой в футере — ссылка на `/settings/notifications`, не токен.

**Тесты и документация**
- [ ] Playwright: карточка представителя без привязки → диалог ссылки → копирование;
      статус «Подключён»; неактивная кнопка без e-mail; фильтр в списке.
- [ ] `Notifications.Tests`: футер добавляется без привязки и не добавляется с ней;
      повторный `IssueTokenAsync` в течение срока возвращает тот же URL.
- [ ] `docs/03 Frontend/Карта экранов.md` (карточки и списки People),
      `docs/02 Модули/Notifications.md` (футер, батч-статус).
