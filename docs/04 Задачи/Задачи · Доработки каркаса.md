Справочник: [[Multitenancy]]

> Сущность `Modules.Multitenancy/Domain/TenantSettings.cs` (по образцу `TenantTheme`,
> живёт в модуле, а не в защищённом `AppTenantInfo`) — `TimeZoneId` (IANA), `Currency`
> (ISO 4217), `ITenantSettingsService` на `HybridCache`, миграция с бэкофиллом
> существующих тенантов, значения по умолчанию (`UTC`/`USD`) при провижининге новой школы,
> права `SchoolSettings.Manage`/`.View`, тест изоляции по тенанту. Это разблокировало
> [[Scheduling]] и [[Payments]]. **Не делается сознательно:** колонка `Settings` (JSONB) —
> пока настроек две, типизированные колонки честнее; завести, когда появится
> третья-четвёртая (рабочие часы, формат номера счёта, поведение при задолженности).

- [x] Шаги провижининга под новые модули: базовые направления [[Curriculum]] по
      умолчанию, тариф по умолчанию [[Payments]] — реализовано. `CurriculumDbInitializer`/
      `PaymentsDbInitializer` пересмотрены с сознательных no-op'ов (комментарии "no per-tenant
      reference data to seed") на минимальный дефолт, тем же механизмом, что уже сидирует
      школьные роли (`TenantService.SeedTenantAsync` резолвит все `IDbInitializer` в scope
      тенанта). Curriculum: два верхнеуровневых `Subject` («Английский язык», «Математика») —
      нужны, потому что `CreateCourseCommand` требует `SubjectId`. Payments: один `Tariff`
      (`Kind = OneTime`, `CourseId: null`, `Amount = 0m`, `Currency` из
      `ITenantSettingsService.GetCurrentAsync()`, не хардкод `"USD"`) — `OneTime` выбран, потому
      что не зависит ни от расписания/посещаемости (`PerLesson`/`PerMonth`), ни от доп. полей
      пакета (`PerPackage`, явно исключён из дефолта). Оба идемпотентны (по `Slug`/`Name`
      соответственно, по образцу `IdentityDbInitializer`). `CourseId: null` держит модули
      независимыми друг от друга — порядок вызова двух `IDbInitializer` не гарантирован. Тесты:
      `Curriculum.Tests`/`Payments.Tests` (юнит, идемпотентность на InMemory-провайдере) +
      `Integration.Tests` →
      `TenantSeedDataTests.NewTenant_Should_BeSeededWith_DefaultSubjects_And_DefaultTariff`
      (реальный Postgres через Testcontainers) — все зелёные, `Architecture.Tests` 51/51,
      `dotnet build` 0 предупреждений/0 ошибок. Обоснование решения — `docs/02 Модули/
      Curriculum.md` и `Payments.md` (примечания в начале файлов). **Открытый шаг:** публичный
      docs-репозиторий (`github.com/fullstackhero/docs`) и changelog не обновлены в этой сессии —
      по опыту предыдущих пяти модулей это отдельная сессия с доступом к тому репозиторию.
- [ ] В UI «Tenant» → «Школа» ([[Задачи · Frontend]])

> [!note] Если всё же понадобится поле в `AppTenantInfo`
> Прецеденты есть — `Plan` и `QuotaLimits` там уже лежат, то есть прикладные поля

### Спецификация «Приглашение по e-mail»

> [!note] Мягкая зависимость от [[People]] снята
> Изначально план был не блокироваться на People (модуля ещё не было). People теперь
> реализован — привязку приглашённого пользователя к `Guardian`/`Student` можно делать
> сразу через существующий `LinkStudentUserCommand`-подобный вызов, отдельного шага
> ждать не нужно.

| Что                         | Как                                                                                                                                                                                                                | Образец в коде                                                                                                                                  |
| --------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| Не новая сущность токена    | Переиспользовать `UserManager.GeneratePasswordResetTokenAsync` — уже с TTL (`DataProtectionTokenProviderOptions`) и одноразовый по факту (инвалидируется сменой security stamp)                                    | механизм уже используется в `ForgotPasswordCommand`/`ResetPasswordCommand`                                                                      |
| Новая команда               | `InviteUserCommand` (email, ФИО, роль) — создаёт `FshUser` со случайным неиспользуемым паролем и `EmailConfirmed = false`, затем сразу генерирует reset-токен и письмо                                             | `RegisterUserCommand` как основа состава полей, но без `Password`/`ConfirmPassword`                                                             |
| Приём приглашения           | Существующий `ResetPasswordCommand` (email + токен + новый пароль). Дополнительно — проставлять `EmailConfirmed = true` при успешном приёме приглашения (получение письма на закрытый ящик уже подтверждает адрес) | `ResetPasswordCommand` handler                                                                                                                  |
| Право на отправку           | Новое `IdentityPermissions.Users.Invite`, отдельное от `Users.Create`                                                                                                                                              | по таблице [[Модель прав доступа]] `Manager` не имеет `Users.*`, кроме этого исключения — приглашать нужно, полный доступ к пользователям — нет |
| Письмо                      | Шаблон через `BuildingBlocks/Mailing` — та же проверка механизма подстановки, что уже стоит в бэклоге [[Notifications]] («Шаблоны сообщений с подстановкой»); не дублировать исследование                          | `ForgotPasswordCommand` уже шлёт письмо тем же каналом                                                                                          |
| Самостоятельная регистрация | `/self-register` не удаляем и не трогаем backend — просто не вызываем из dashboard UI. Инвайт становится единственным путём получить доступ представителю/ученику на практике                                      | `SelfRegisterUserEndpoint` (анонимный, уже рейт-лимитирован)                                                                                    |
