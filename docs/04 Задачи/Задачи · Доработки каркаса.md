## Multitenancy · блокирующее

Справочник: [[Multitenancy]]

> [!danger] `AppTenantInfo` лежит в защищённом каталоге
> Файл — `src/BuildingBlocks/Shared/Multitenancy/AppTenantInfo.cs`, то есть добавление
> в него полей нарушает правило 4 из `AGENTS.md` и требует явного согласования
> (`.agents/rules/buildingblocks-protection.md`). Само правило предписывает сначала
> искать решение внутри модуля.
>
> **Решение: сущность `TenantSettings`, принадлежащая `Modules.Multitenancy`.**
> Прецедент рядом — `TenantTheme`: такая же пер-тенантная сущность с `IHasTenant`,
> живущая в модуле, а не в BuildingBlocks.

### Спецификация `TenantSettings`

> ✅ Реализовано. Всё скопировано с `TenantTheme` — он решает ровно ту же задачу
> «данные на тенант, живущие в модуле».

| Что          | Как                                                                                                                                          | Образец в коде                                    |
| ------------ | -------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------- |
| Сущность     | `Modules.Multitenancy/Domain/TenantSettings.cs`, `BaseEntity<Guid>`, `IHasTenant`, `IAuditableEntity`                                        | `Domain/TenantTheme.cs`                           |
| DbContext    | `DbSet<TenantSettings>` в `TenantDbContext`                                                                                                  | там же `TenantThemes`                             |
| Конфигурация | `ToTable("TenantSettings", MultitenancyConstants.Schema)`, **уникальный индекс по `TenantId`**, `TenantId` — `HasMaxLength(64).IsRequired()` | `Data/Configurations/TenantThemeConfiguration.cs` |
| Сервис       | `ITenantSettingsService` в Contracts, метод `GetCurrentAsync(ct)` — текущий тенант резолвится внутри                                         | `ITenantThemeService.GetCurrentTenantThemeAsync`  |
| Кэш          | **`HybridCache`**, а не самодельный Redis: `HybridCacheEntryOptions` + теги `CacheKeys.Tags.Tenant(tenantId)`, локальная экспирация ~2 мин   | `Services/TenantThemeService.cs`                  |
| Инвалидация  | по тегу тенанта при обновлении настроек                                                                                                      | там же                                            |

> [!important] `TenantDbContext` — глобальный реестр, а не изолированный контекст
> Он наследует `EFCoreStoreDbContext<AppTenantInfo>`, автоматической фильтрации по
> тенанту в нём нет. Поэтому `TenantId` — **явная колонка с уникальным индексом**,
> ровно как у `TenantTheme`. Не пытайтесь опираться на `BaseDbContext`.

- [x] Сущность, конфигурация, `DbSet`, миграция (`AddTenantSettings`,
      `src/Host/Edvantix.Migrations.PostgreSQL/MultiTenancy/`)
- [x] `TimeZoneId` (IANA) — **блокирует весь [[Scheduling]]**
- [x] `Currency` (ISO 4217, `HasMaxLength(3)`) — **блокирует [[Payments]]**
- [x] `ITenantSettingsService` + `TenantSettingsService` на `HybridCache`
- [x] `GetTenantSettingsQuery` / `UpdateTenantSettingsCommand` + валидатор
- [x] Валидатор `TimeZoneId`: `TimeZoneInfo.TryFindSystemTimeZoneById`.
      Логика платформо-независима (.NET понимает IANA-идентификаторы через ICU
      на Windows и на Linux); фактический прогон на Linux CI/prod ещё предстоит
      увидеть — тест написан, но здесь исполнялся только на Windows
- [x] Значения по умолчанию при провижининге нового тенанта — `CreateTenantCommand`
      принимает необязательные `TimeZoneId`/`Currency`, `CreateTenantCommandHandler`
      создаёт `TenantSettings` сразу вместе с `AppTenantInfo`
- [x] Бэкофилл существующих тенантов в миграции — SQL-вставка в `Up()` миграции
      `AddTenantSettings` для тенантов без строки настроек
- [x] Тест: настройки школы A не видны под школой B —
      `Integration.Tests/Tests/Multitenancy/TenantSettingsTests.cs`
      (+ `Multitenancy.Tests/Domain/TenantSettingsTests.cs` на сущность)

**Не делать в первой итерации:** колонку `Settings` (JSONB). Пока настроек две,
типизированные колонки честнее; JSONB завести, когда появится третья-четвёртая
(рабочие часы, формат номера счёта, поведение при задолженности, начало учебного года).

### Решения, принятые до кода

| Вопрос | Решение |
|---|---|
| Часовой пояс по умолчанию | `UTC` |
| Валюта по умолчанию | `USD` |
| Право на правку | новое `SchoolSettings.Manage` (не `Tenants.Update` — тот операторский/root) |
| Право на чтение | `SchoolSettings.View`, `IsBasic: true` — часовой пояс и валюта нужны фронтенду на каждом экране |
| Задаются ли при создании школы | да — `CreateTenantCommand.TimeZoneId`/`Currency` (необязательные, дефолт UTC/USD) |
| Нужны ли настройки root-тенанту | да, создаются со значениями по умолчанию (`Edvantix.DbMigrator/Program.cs`, шаг сидирования root-тенанта) |

> [!note] Ещё не сделано
> Роль `SchoolAdmin` (см. раздел [[#Identity]] ниже) пока не засеяна, поэтому
> `SchoolSettings.Manage` фактически достаётся роли `Admin` (получает все
> не-root права по умолчанию через `RolePermissionSyncer`). Ограничение на
> `SchoolAdmin` — когда появится сид ролей школы. Правка UI «Tenant» → «Школа»
> ([[Задачи · Frontend]]) тоже не сделана — это отдельная задача.
