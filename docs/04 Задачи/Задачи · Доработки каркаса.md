## Multitenancy · блокирующее

Справочник: [[Multitenancy]]

> [!danger] `AppTenantInfo` лежит в защищённом каталоге
> Файл — `src/BuildingBlocks/Shared/Multitenancy/AppTenantInfo.cs`, то есть добавление
> в него полей нарушает правило 4 из `AGENTS.md` и требует явного согласования
> (`.agents/rules/buildingblocks-protection.md`). Само правило предписывает сначала
> искать решение внутри модуля.
>
> **Решение: сущность `TenantSettings`, принадлежащая `Modules.Multitenancy`.**
> Прецедент рядом — `TenantTheme`: такая же пер-тенантная сущность с `IHasTenant`,
> живущая в модуле, а не в BuildingBlocks.

### Спецификация `TenantSettings`

Всё копируется с `TenantTheme` — он решает ровно ту же задачу «данные на тенант,
живущие в модуле».

| Что          | Как                                                                                                                                          | Образец в коде                                    |
| ------------ | -------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------- |
| Сущность     | `Modules.Multitenancy/Domain/TenantSettings.cs`, `BaseEntity<Guid>`, `IHasTenant`, `IAuditableEntity`                                        | `Domain/TenantTheme.cs`                           |
| DbContext    | `DbSet<TenantSettings>` в `TenantDbContext`                                                                                                  | там же `TenantThemes`                             |
| Конфигурация | `ToTable("TenantSettings", MultitenancyConstants.Schema)`, **уникальный индекс по `TenantId`**, `TenantId` — `HasMaxLength(64).IsRequired()` | `Data/Configurations/TenantThemeConfiguration.cs` |
| Сервис       | `ITenantSettingsService` в Contracts, метод `GetCurrentAsync(ct)` — текущий тенант резолвится внутри                                         | `ITenantThemeService.GetCurrentTenantThemeAsync`  |
| Кэш          | **`HybridCache`**, а не самодельный Redis: `HybridCacheEntryOptions` + теги `CacheKeys.Tags.Tenant(tenantId)`, локальная экспирация ~2 мин   | `Services/TenantThemeService.cs`                  |
| Инвалидация  | по тегу тенанта при обновлении настроек                                                                                                      | там же                                            |

> [!important] `TenantDbContext` — глобальный реестр, а не изолированный контекст
> Он наследует `EFCoreStoreDbContext<AppTenantInfo>`, автоматической фильтрации по
> тенанту в нём нет. Поэтому `TenantId` — **явная колонка с уникальным индексом**,
> ровно как у `TenantTheme`. Не пытайтесь опираться на `BaseDbContext`.

- [ ] Сущность, конфигурация, `DbSet`, миграция
- [ ] `TimeZoneId` (IANA) — **блокирует весь [[Scheduling]]**
- [ ] `Currency` (ISO 4217, `HasMaxLength(3)`) — **блокирует [[Payments]]**
- [ ] `ITenantSettingsService` + `TenantSettingsService` на `HybridCache`
- [ ] `GetTenantSettingsQuery` / `UpdateTenantSettingsCommand` + валидатор
- [ ] Валидатор `TimeZoneId`: `TimeZoneInfo.TryFindSystemTimeZoneById`.
      .NET 6+ понимает IANA-идентификаторы и на Windows через ICU, но проверить
      надо на обеих платформах — разработка на Windows, CI и прод на Linux
- [ ] Значения по умолчанию при провижининге нового тенанта
- [ ] Бэкофилл существующих тенантов в миграции
- [ ] Тест: настройки школы A не видны под школой B

**Не делать в первой итерации:** колонку `Settings` (JSONB). Пока настроек две,
типизированные колонки честнее; JSONB завести, когда появится третья-четвёртая
(рабочие часы, формат номера счёта, поведение при задолженности, начало учебного года).

### Решения, которые нужно принять до кода

| Вопрос | Варианты | Предложение |
|---|---|---|
| Часовой пояс по умолчанию | `UTC` · `Europe/Moscow` · обязательное поле при создании школы | зависит от рынка — решает владелец продукта |
| Валюта по умолчанию | `RUB` · `USD` (текущий дефолт `BillingPlan`) | то же |
| Право на правку | новое `SchoolSettings.Manage` · существующее `Tenants.Update` | новое: настройки школы правит `SchoolAdmin`, а `Tenants.Update` — операторское |
| Право на чтение | всем аутентифицированным (`IsBasic`) · отдельное | `IsBasic`: часовой пояс и валюта нужны фронтенду на каждом экране |
| Задаются ли при создании школы | расширить `CreateTenantCommand` · дефолт + правка потом | расширить: иначе первая же сгенерированная неделя расписания уедет на несколько часов |
| Нужны ли настройки root-тенанту | да · нет | создавать со значениями по умолчанию: дешевле, чем ветвление на `null` в каждом обращении |
