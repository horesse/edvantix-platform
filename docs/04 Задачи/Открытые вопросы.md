# Открытые вопросы

← [[Бэклог]]

Формат: вопрос → варианты → предварительное предложение → когда решать.

## Scheduling

### Отработка пропущенного занятия в другой группе

Учитывать в посещаемости обеих групп? Как тарифицировать?

**Предложение:** отдельная сущность `MakeupSession` — **за пределами MVP**.
Пока отработка оформляется разовым занятием без `LessonId`.

### Замена преподавателя на одном занятии

Моделью поддержано (`Session.TeacherId` переопределяет шаблон). Открыто: нужен ли
отдельный статус занятия и уведомление ученикам о замене.

### Экспорт расписания в iCal

Попросят почти сразу. Реализуемо тонким эндпоинтом поверх `GetMyScheduleQuery`.
Вопрос только в приоритете.

## Payments

### Нумерация счетов

Сквозная по школе или с обнулением по годам? Формат номера? **Не решено** на уровне
кода — счета сейчас нумеруются рабочей схемой без настраиваемого шаблона (см. [[Payments]]).

**Предложение:** настройка тенанта с шаблоном (`{YYYY}-{NNNN}`), по умолчанию сквозная.
Требования разные у разных юрисдикций.

### Закрывающие документы (акты)

Зависит от юрисдикции школы. Пока нет; уточнить у первых клиентов.

### Автоблокировка доступа при задолженности

Просят часто. Продуктовое решение, не техническое.

**Предложение:** флаг тенанта, по умолчанию выключен. Блокировать материалы, но не
расписание — иначе ученик просто не придёт на занятие, которое школа уже оплатила
преподавателю.

## People

### Дедупликация

Два «Иванов Иван» с одним телефоном.

**Варианты:** мягкое предупреждение при создании · жёсткий уникальный индекс по телефону.

**Предложение:** предупреждение. Жёсткий индекс сломается на семьях с одним контактным
телефоном на всех детей.

### Согласие на обработку персональных данных

Хранить дату и версию текста согласия? Для России и ЕС — вероятно, да. Уточнить
требования до продакшена.

## Curriculum

### Версионирование курса

Если курс правят посреди потока, должна ли группа видеть версию на момент старта?

**Предложение:** в MVP — ручное дублирование (`DuplicateCourseCommand`). Полноценные
версии — отложено.

### Прогресс по программе

«Прошли 12 из 40 уроков». Считать на лету из проведённых `Session` с непустым `LessonId`
или хранить проекцию?

**Предложение:** на лету, пока не станет медленно.

## StudyGroups

### Индивидуальные занятия 1:1

**Варианты:** отдельная сущность · группа с `Capacity = 1`.

**Предложение:** второе. Меньше кода, единое расписание и тарификация.

### Лист ожидания

При заполненной группе. Отложено; пока — заметка менеджера.

### Слияние групп

Две малые в одну. Ручной перевод учеников по одному достаточен для MVP.

## Chat

### Границы чата

Ценность для школы узкая: объявления группе и вопросы преподавателю.

**Предложение:** модерацию и ботов не делать. Треды уже есть (`ListMessageRepliesQuery`) —
оставить как есть.
