# EDX-013 · Настраиваемый шаблон номера счёта ученика

> [!success] Готово · 2026-09-03 · branch `claude/edx-013-173ce3`
> Продуктовое решение по плейсхолдерам зафиксировано в [[Payments]] → «Нумерация счетов»;
> политика обнуления выводится из шаблона (год в шаблоне → сброс по годам), отдельного
> тумблера нет. `TenantSettings.InvoiceNumberTemplate` (дефолт `{YYYY}-{NNNN}`),
> `IInvoiceNumberGenerator` с атомарным резервированием блока номеров
> (`INSERT … ON CONFLICT DO UPDATE … RETURNING` по `payments."InvoiceNumberSequences"`),
> две миграции + бэкофилл дефолта, юнит- и интеграционные тесты.

## Контекст

`StudentInvoice.GenerateNumber` нумерует счета рабочей схемой без настраиваемого
шаблона (см. `docs/02 Модули/Payments.md`; в PR #12 чинился баг коллизий на пакетном
выпуске — брались старшие биты Guid v7 вместо младших). Из [[Открытые вопросы]] →
Payments: нужна настройка тенанта с шаблоном (`{YYYY}-{NNNN}`), по умолчанию сквозная;
требования отличаются по юрисдикциям.

`clients/dashboard/src/pages/settings/school.tsx:250` уже показывает секцию
«Нумерация счетов» с текстом «задаётся сервером автоматически и не настраивается из
интерфейса» — ждёт эту задачу.

## Что сделано

- [x] Продукт: плейсхолдеры `{YYYY}` / `{YY}` / `{MM}` / `{N…}` (маска ширины счётчика);
      политика обнуления **выводится из шаблона** — год в шаблоне ⇒ счётчик сбрасывается
      по календарным годам, иначе сквозной; отдельного тумблера нет (EDX-014 может его не
      добавлять). Смена шаблона посреди года не сбрасывает счётчик текущего scope. Решение
      записано в [[Payments]] → «Нумерация счетов», пункт убран из [[Открытые вопросы]].
- [x] `TenantSettings.InvoiceNumberTemplate` в `Modules.Multitenancy` (рядом с TZ/валютой),
      дефолт `{YYYY}-{NNNN}`; в DTO/команде/валидаторе; `null` в команде = «не менять».
- [x] Генерация номера вынесена из доменной фабрики в `IInvoiceNumberGenerator`
      (`Modules.Payments`): читает шаблон тенанта, резолвит scope, атомарно резервирует блок
      номеров одним `INSERT … ON CONFLICT ("TenantId","Scope") DO UPDATE …  RETURNING` по
      `payments."InvoiceNumberSequences"` — конкурентные пакеты сериализуются на блокировке
      строки. `StudentInvoice.Create` теперь принимает готовый `number`.
- [x] Миграции `AddInvoiceNumberTemplate` (Multitenancy, бэкофилл дефолта) и
      `AddInvoiceNumberSequence` (Payments, таблица счётчиков). Юнит-тесты
      `InvoiceNumberFormatTests`; интеграционный `InvoiceNumberTemplateTests` (шаблон
      применяется к новому счёту; 100 номеров в один параллельный залп — уникальны,
      без разрывов, монотонны).
