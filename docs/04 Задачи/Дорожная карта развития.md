# Дорожная карта развития

← [[Бэклог]] · [[Этапы внедрения]] · [[Продуктовое видение]]

> [!info] Что это
> План «что добавить, чтобы школы выбирали Edvantix». Этапы 0–7 ([[Этапы внедрения]])
> закрыли MVP; в [[Бэклог|Бэклоге]] остались пять мелких хвостов. Дальше вопрос не
> «что доделать», а «за что нас купят». Здесь — ответ, разбитый на три горизонта.
> Когда пункт берётся в работу, он заводится задачей `EDX-NNN` и здесь остаётся ссылкой.

## Где мы

Сильная сторона — бэк-офис: расписание с часовыми поясами и конфликтами, четыре модели
тарификации, сторно, аудит каждого действия, гибкие права, кабинеты ученика и представителя.
Это уровень зрелых школьных CRM, а не стартового прототипа.

Слабая сторона — всё, что **вокруг** бэк-офиса:

| Граница | Что сейчас | Что ждёт школа |
|---|---|---|
| Вход клиентов | `Student.Status = Lead`, заявку заводит менеджер | форма с сайта, воронка, пробное занятие, конверсия |
| Выход денег | счёт → родитель платит переводом → менеджер подтверждает вручную | кнопка «Оплатить» в кабинете, автозачёт |
| Связь | почта + колокольчик в приложении | Telegram / WhatsApp, куда родитель реально смотрит |
| Учебный результат | материалы урока, посещаемость | домашние задания, проверка, обратная связь родителю |
| Владелец | отчёты «должники» и «поступления» | выручка, заполняемость, отток, зарплаты |
| Переезд | импорт людей из CSV | перенести всё из «Мой Класс» / таблиц за вечер |

## Кто выбирает и по каким критериям

Целевой клиент: языковая, IT-, музыкальная школа, репетиторский центр, детская студия
на 50–500 учеников. Сравнивают с «Мой Класс», Alfa CRM, Hollihop (CRM для школ),
GetCourse / Teachbase (LMS с маркетингом) и с Google Sheets.

Что решает при выборе, по убыванию веса:

1. **Переезд без потерь** — если импорт неполный, школа не переходит вообще.
2. **Родители платят сами, онлайн** — менеджер перестаёт гоняться за чеками.
3. **Уведомления в мессенджере** — письма родители не читают.
4. **Индивидуальные занятия и переносы самим учеником** — критично репетиторским центрам.
5. **Домашние задания и результаты** — школа выглядит серьёзной в глазах родителя.
6. **Отчёты владельцу** — деньги, загрузка, отток, зарплаты.
7. **Цена и скорость старта** — бесплатный план уже есть ([[Billing]]).

Каждый пункт горизонта ниже ссылается на номер критерия, который он закрывает.

## Горизонт 1 · 0–3 мес — убрать причины отказа

Без этих шести пунктов школа выбирает конкурента даже при лучшем бэк-офисе.

### 1.1 Онлайн-оплата счетов (критерий 2)

**Что.** Платёжная ссылка в счёте и кнопка «Оплатить» на `/my/invoices`. Школа подключает
**свой** мерчант (ЮKassa, Т-Банк, bePaid, Stripe — через адаптер `IPaymentProvider`).
Вебхук провайдера → `PaymentConfirmation` с `Method = Online`, `Reference = id платежа`,
`ConfirmedByUserId = system`. Частичная оплата и переплата уже поддержаны моделью.

**Почему не ломает [[ADR-004 Payments отдельно от Billing]].** Деньги по-прежнему идут
школе напрямую; платформа лишь заменяет ручную отметку менеджера автоматической.
ADR дополняется, не пересматривается.

**На чём строим.** Inbox/идемпотентность из `BuildingBlocks/Eventing` для вебхуков
провайдера; анонимный маршрут с `?tenant=` по образцу iCal ([[EDX-012 Экспорт расписания в iCal]]);
секреты мерчанта — в `TenantSettings`, **шифрованные** (Data Protection; потребует
согласования по `BuildingBlocks`).

**Размер.** L. Отдельный модуль `PaymentGateways`, чтобы Payments не зависел от HTTP-клиентов провайдеров.

### 1.2 Telegram как канал уведомлений (критерий 3)

→ развязано в задачи: зонтик [[EDX-021 Telegram-уведомления]] (решения) и
EDX-022…EDX-031 (см. [[Бэклог]]).

**Что.** `NotificationChannelKind.Telegram` рядом с `InApp | Email`. Один бот платформы;
привязка — deep-link `/start <token>` из кабинета, а для людей без учётной записи —
по номеру телефона из [[People]] (бот просит «поделиться контактом»). Напоминание о
занятии за 24 ч и за 1 ч, отмена/перенос, счёт, просрочка.

**На чём строим.** Диспетчер уже разливает одно уведомление по каналам-флагам; нужен только
новый `INotificationChannel` и таблица привязок chat-id. Настройки подписок и тихие часы — как есть.

**Размер.** M. WhatsApp Business API — позже, он платный и с модерацией шаблонов.

### 1.3 PDF-документы (критерии 2, 6)

**Что.** Счёт в PDF с реквизитами школы, квитанция об оплате, договор-оферта из шаблона
с подстановкой (ученик, тариф, период). Реквизиты и шаблон договора — в настройках школы.
Файлы — в [[Files]], ссылка из карточки счёта и кабинета.

**Размер.** M. Рендер HTML → PDF (QuestPDF или headless Chromium в отдельном воркере).
Закрывает «закрывающие документы» из [[Открытые вопросы]] в части квитанций; акты — по запросу первых клиентов.

### 1.4 Мастер переезда (критерий 1)

**Что.** Один экран «Импорт»: люди (есть), группы, зачисления с тарифом, расписание
(шаблоны или готовые занятия), **входящие балансы** (долг / аванс / остаток пакета
одной строкой `OneTime`-счёта). Предпросмотр, отчёт об ошибках по строкам, откат
импорта целиком. Готовые маппинги колонок под экспорт «Мой Класс» и Alfa CRM.

**Размер.** M. Каждый модуль уже имеет команды; нужен оркестратор в хосте и UI.

### 1.5 Заявки и воронка (критерий 1, 7)

**Что.** Отдельный модуль `Leads`: заявка (источник, контакт, интерес к курсу),
стадии `Новая → Связались → Пробное → Ожидает оплаты → Ученик / Отказ`, ответственный,
задача-напоминание «перезвонить», причина отказа. Публичный endpoint + встраиваемая
форма для сайта школы. Пробное занятие — `Session` без группы с ссылкой на заявку.
Конверсия в ученика — команда, которая создаёт `Student` и переносит контакты.

**Почему отдельный модуль.** [[People]] обязан оставаться низовым; воронка тянет
Scheduling (пробное) и Payments (первый счёт).

**Размер.** L. Канбан на дашборде + список + карточка.

### 1.6 Начисления преподавателям (критерий 6)

**Что.** `Teacher.HourlyRate` уже есть. Отчёт «начислено за период»: проведённые занятия ×
ставка; варианты ставки — за час, за занятие, процент от тарифа группы. Правило «платить
ли за занятие, где никто не пришёл». Экспорт в Excel. Без выплат и без бухгалтерии.

**Размер.** S–M. Всё в [[Scheduling]] + People, по образцу `GetTeacherWorkloadQuery`.

## Горизонт 2 · 3–6 мес — чем отличаемся

### 2.1 Домашние задания и обратная связь (критерий 5)

**Что.** Модуль `Homework`: задание к уроку программы или к конкретному занятию, сдача
учеником (текст/файл/ссылка), проверка преподавателем с оценкой по шкале школы и
комментарием. Родитель видит статус в кабинете. Короткий отзыв преподавателя после занятия
(«что делали, над чем работать») — та же сущность без задания. Тестов и конструктора
квизов на этом шаге нет — см. 3.3.

**Размер.** L. Самый заметный шаг к «LMS-lite», отличает от чистых CRM.

### 2.2 Индивидуальные занятия и самозапись (критерий 4)

**Что.** Доступность преподавателя (слоты по дням недели + исключения), запись ученика на
свободный слот из кабинета, перенос/отмена самим учеником в пределах правил школы
(«не позднее чем за N часов», лимит переносов на пакет). Отработка пропуска (`MakeupSession`
из [[Открытые вопросы]]). Лист ожидания на заполненную группу.

**Размер.** L. Всё в [[Scheduling]] / [[StudyGroups]]; 1:1 остаётся группой с `Capacity = 1`.

### 2.3 Аналитика владельца (критерий 6)

**Что.** Экран «Показатели»: начисления / оплаты / долг по месяцам, заполняемость групп,
приток и отток учеников, посещаемость по группам и преподавателям, конверсия заявок (после 1.5),
LTV ученика. Список **«в зоне риска»** — падение посещаемости + долг + нет активности в кабинете.
Экспорт Excel на каждом списке платформы.

**Размер.** M. Read-side запросы поверх существующих данных; для 200 учеников считается на лету.

### 2.4 Видеосвязь в занятии (критерий 4)

**Что.** `Session.MeetingUrl` уже есть. Автосоздание ссылки при генерации занятий
(Zoom, Google Meet, Jitsi без ключей), кнопка «Войти» за 10 минут до начала, ссылка
на запись после. Посещаемость по факту входа — опционально.

**Размер.** M. Адаптеры провайдеров по образцу вебхуков.

### 2.5 Мобильный опыт: PWA и push (критерий 3)

**Что.** Установка на телефон, Web Push как ещё один `NotificationChannelKind`,
офлайн-кэш расписания. Нативных приложений не делаем.

**Размер.** M.

### 2.6 Соответствие требованиям (критерий 7)

**Что.** Согласие на обработку ПДн: дата, версия текста, кто принял (из [[Открытые вопросы]]).
Реквизиты школы для документов (1.3). Двухфакторная аутентификация для админов школы.
Экспорт и удаление данных ученика по запросу.

**Размер.** S.

## Горизонт 3 · 6–12 мес — платформа

### 3.1 Публичный каталог и самозапись

Витрина курсов школы на своём домене и бренде (`TenantTheme` уже есть), запись в группу
или на пробное, оплата онлайн (1.1). Замыкает воронку: сайт → заявка → оплата → ученик
без участия менеджера. **L.**

### 3.2 Публичный API и интеграции

[[EDX-008 API-ключи в Identity]] + [[EDX-009 Экран API-ключей в настройках]], затем
коннекторы Zapier / Make / n8n поверх [[Webhooks]], выгрузка в 1С и бухгалтерию. **M.**

### 3.3 Тесты и сертификаты

Квизы с автопроверкой на уроке, порог прохождения, сертификат PDF по завершении курса
(шаблон школы). **L.** Логичное продолжение 2.1.

### 3.4 AI-помощник

Отдельные небольшие функции, каждая по **M**, на Claude API:

- план урока и материалы по теме и уровню — в конструкторе курса;
- курс из программы: загрузил PDF/DOCX → разделы и уроки;
- конспект занятия из записи (после 2.4) — родителю и в историю;
- «кому написать сегодня» менеджеру: должники, риск оттока, заявки без движения;
- вопрос по данным школы на естественном языке («сколько заработала группа EN-A1 в мае»).

### 3.5 Филиалы

Несколько локаций одной школы: филиал у аудитории, преподавателя, группы; часовой пояс
на филиал; фильтр по филиалу на всех экранах. **M.** Мультивалюта — нет, валюта одна на тенант.

### 3.6 Версионирование курса

Из [[Открытые вопросы]]: группа видит версию программы на момент старта. Пока хватает
`DuplicateCourseCommand`; переходить, когда первые школы упрутся. **L.**

## Расширения существующего — быстрые победы

Каждое S, можно брать между крупными пунктами:

- **Замена преподавателя на занятии** → уведомление ученикам и отметка в карточке (из [[Открытые вопросы]]).
- **Автопродление пакета** — остаток `PerPackage` ≤ 1 → черновик нового счёта + уведомление родителю.
- **Напоминание об остатке пакета** родителю и менеджеру.
- **Правила скидок** — семейная (второй ребёнок), промокод, скидка за годовую оплату; сейчас скидка только вручную на зачислении.
- **Массовые операции в расписании** — перенести все занятия группы на неделю, сменить преподавателя на период, отменить день по всей школе.
- **Drag-and-drop** переноса занятия в календаре.
- **Утренний дайджест** преподавателю (сегодняшние занятия) и менеджеру (занятия без преподавателя, новые должники, заявки).
- **Экспорт Excel** на всех списках, не только `Students.Export`.
- **Мастер первого запуска** — курс → группа → расписание за пять шагов + демо-данные в бесплатном плане.
- **Брендирование писем** школы через `TenantTheme`.
- **Английская локаль дашборда** — выход за пределы RU/BY.

## Что осознанно не делаем

| Не делаем | Почему |
|---|---|
| Свой платёжный шлюз / приём денег на счёт платформы | лицензии и ответственность; школа подключает свой мерчант (1.1) |
| Нативные мобильные приложения | PWA + push закрывают 90 % (2.5) |
| Своя видеосвязь | интеграции с Zoom/Meet/Jitsi (2.4) |
| Полноценный конструктор курсов уровня GetCourse | наша ниша — операционка школы с LMS-lite, не платформа инфобизнеса |
| Мультивалюта внутри тенанта | одна валюта на школу; вторая валюта — вторая школа |
| Чат-боты и модерация в чате | ценность чата узкая (см. [[Открытые вопросы]]) |

## Порядок старта

Первые пять задач, в этом порядке. Логика: сначала быстрые и видимые, чтобы каждые
две-три недели было что показать; крупные — параллельно.

| # | Пункт | Размер | Почему первым |
|---|---|---|---|
| 1 | 1.2 Telegram-уведомления | M | самая заметная для родителей функция, канал-абстракция готова |
| 2 | 1.6 Начисления преподавателям | S–M | владелец видит деньги, данные уже есть |
| 3 | 1.3 PDF счёта и квитанции | M | нужно для 1.1 и для «серьёзности» |
| 4 | 1.1 Онлайн-оплата | L | главный критерий выбора, самая длинная задача — начинать сразу |
| 5 | 1.4 Мастер переезда | M | без него не будет второго клиента |

Затем 1.5 Заявки, и горизонт 2 начиная с 2.1 Домашние задания.

## Как поймём, что работает

| Метрика | Цель |
|---|---|
| Школа ведёт полный месяц в системе (критерий MVP) | каждая подключённая школа, к концу второго месяца |
| Доля счетов, оплаченных онлайн | > 50 % через три месяца после 1.1 |
| Доля уведомлений, доставленных в Telegram | > 70 % родителей привязали бот |
| Время от регистрации до первого сгенерированного расписания | < 1 час |
| Школы, переехавшие с другой системы через мастер | без ручных правок в БД |
