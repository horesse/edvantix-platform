### Проектные решения, принятые при реализации (расширяют справочник [[Curriculum]])

- **Плоская персистентность, не вложенный агрегат.** `Course`, `CourseModule`, `Lesson`,
  `LessonMaterial` — четыре независимых `AggregateRoot` со своим `DbSet` и FK на родителя
  (`CourseModule.CourseId`, `Lesson.CourseModuleId`, `LessonMaterial.LessonId`), а не
  `Course`, владеющий всем деревом как EF owned-коллекциями. Причина: конструктор курса на
  фронте — это автосохранение отдельного урока/материала за один запрос; перечитывать и
  сохранять весь агрегат `Course` (потенциально сотни уроков) на каждую мелкую правку —
  не тот путь. `GetCourseByIdQuery` собирает `CourseDetailDto` явным join'ом трёх `DbSet`
  в хендлере, а не через навигационные свойства. Паттерн `Product.Images` из Catalog
  (owned-коллекция) используется только внутри `Product` — здесь не подходит из-за трёх
  уровней вложенности.
- **Мягкое удаление — только у `Course`.** Только `Course` реализует `ISoftDeletable` (корзина +
  `RestoreCourseCommand` + `ListTrashedCoursesQuery` — см. таблицу «Команды»/«Запросы» в
  справочнике). У `Subject`/`CourseModule`/`Lesson`/`LessonMaterial` нет команд восстановления
  в контрактах → `Delete`/`Remove` для них обычное жёсткое удаление (нет `ISoftDeletable`,
  интерцептор их не перехватывает). Это сознательное упрощение, не пробел: заводить корзину
  без единого экрана восстановления — лишняя сложность.
- **Публикация требует хотя бы один раздел.** Инвариант «курс без разделов недопустим» из
  справочника проверяется в `PublishCourseCommandHandler`: `Courses.Publish` на курсе без
  `CourseModule` бросает `CustomException` 409. Создание разделов/уроков остаётся ручным
  через `CreateCourseModuleCommand`/`CreateLessonCommand` — авто-создания скрытого раздела
  «Основной» в `CreateLessonCommand` не делаем (усложнило бы контракт: `Lesson` уже требует
  `CourseModuleId`).
- **`DuplicateCourseCommand`** — глубокое копирование: новый `Course` в статусе `Draft`
  (`PublishedAtUtc = null`), заголовок с суффиксом «(копия {8 hex-символов guid})» — не просто
  «(копия)», иначе второй дубликат того же курса конфликтует с уникальным индексом на `Slug` —
  новый слаг, тот же `SubjectId`/`CoverFileId`; следом клонируются все `CourseModule` → `Lesson`
  → `LessonMaterial` с новыми `Id` (`Guid.CreateVersion7()`), сохраняя `SortOrder`.
- **`LessonMaterialAccessPolicy.OwnerType = "LessonMaterial"`**, `OwnerId` = `LessonId`
  (файл принадлежит уроку, не отдельному материалу) — по образцу `ProductFileAccessPolicy`
  (`OwnerType = "Product"`). `CanAttach` — любой аутентифицированный (эндпоинт `Lessons.Update`/
  `LessonMaterials.Manage` — реальный гейт); `CanRead` — открыто (видимость ученику решает
  `VisibleToStudents` на самом материале, не файловая политика); `CanDelete` — только автор
  загрузки.
