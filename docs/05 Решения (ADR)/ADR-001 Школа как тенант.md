# ADR-001 Школа как тенант

← [[Edvantix]]

**Статус:** принято · 2026-08-09

## Контекст

Стартер-кит содержит развитый модуль [[Multitenancy]] (Finbuckle, провижининг, темы,
сроки действия) и [[Billing]] для подписок тенантов. Нужно решить, что считать тенантом
в предметной области онлайн-школ, — от этого зависит судьба обоих модулей.

Рассмотренные варианты:

1. **Школа = тенант.** Многие школы на одной инсталляции, Edvantix продаётся по подписке.
2. **Одна инсталляция = одна школа.** Multitenancy схлопывается, Billing переориентируется
   на оплаты учеников.
3. **Тенант = филиал школы.** Изоляция между филиалами, единый биллинг сверху.

## Решение

**Вариант 1: школа = тенант.**

## Обоснование

- Модуль [[Multitenancy]] работает и покрыт тестами. Удалять готовую изоляцию, чтобы потом
  писать её заново при первом же втором клиенте, — потеря дважды.
- Изоляция данных между школами обязательна: персональные данные детей, финансы.
  Дефолтная фильтрация в `BaseDbContext` даёт это без усилий разработчика.
- SaaS-модель монетизации ([[Billing]]) получается бесплатно.
- Вариант 2 не отменяет работы: даже одиночной школе нужны роли и права, а изоляция
  просто не мешает.
- Вариант 3 (филиалы) решает более редкую задачу и требует дополнительного уровня
  агрегации. При необходимости филиалы моделируются позже как справочник внутри тенанта.

## Последствия

**Положительные**

- [[Multitenancy]] и [[Billing]] остаются как есть, доработки косметические
- Изоляция школ по умолчанию, обойти её трудно
- Готовы провижининг, темы, сроки действия, деактивация
- Два контура денег естественно разделяются ([[ADR-004 Payments отдельно от Billing]])

**Отрицательные / принимаемые**

- Ни одна предметная сущность не может быть глобальной. Общая библиотека курсов между
  школами невозможна без отдельной модели владения — сознательно отказываемся.
- Кросс-школьная аналитика доступна только оператору через root-тенант
- Разработчик обязан помнить про `base.OnModelCreating` последним в каждом новом
  `DbContext` — иначе фильтры затрутся

**Требуемые доработки**

- Часовой пояс школы — блокирует [[Scheduling]]
- Валюта школы — нужна [[Payments]]
- Шаги провижининга для новых модулей

Оба поля заводятся в сущности `TenantSettings` внутри модуля, а не в `AppTenantInfo`:
последний лежит в защищённом `src/BuildingBlocks`. См. [[Бэклог]].
