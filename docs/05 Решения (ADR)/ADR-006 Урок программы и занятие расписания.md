# ADR-006 Урок программы и занятие расписания

← [[Edvantix]]

**Статус:** принято · 2026-08-09

## Контекст

Слово «урок» означает две разные вещи:

1. **Единица программы** — «Урок 7: Past Simple». Тема, цели, материалы. Существует
   независимо от дат и людей, описывается один раз для курса.
2. **Событие в календаре** — «вторник, 12 марта, 18:00, группа EN-A1-03, Петрова И.».
   Имеет время, преподавателя, аудиторию, посещаемость, статус.

Если смешать, получится сущность с полями `Title`, `Objectives`, `StartUtc`, `TeacherId`,
`Status` — и невозможностью ответить, что делать, когда группа проходит урок 7 повторно
или две группы проходят его в разные дни.

## Решение

Две сущности в двух модулях:

| | `Curriculum.Lesson` | `Scheduling.Session` |
|---|---|---|
| Русское имя | **урок программы** | **занятие** |
| Модуль | [[Curriculum]] | [[Scheduling]] |
| Привязка ко времени | нет | `StartUtc`, `EndUtc` |
| Привязка к людям | нет | преподаватель, посещаемость |
| Принадлежит | разделу курса | учебной группе |
| Сколько экземпляров | один на курс | по одному на каждую группу и дату |
| Кто создаёт | методист, один раз | генератор расписания или менеджер |

Связь: `Session.LessonId` — **nullable** ссылка «какой урок программы проходим».

## Обоснование

**Отношение один-ко-многим неизбежно.** Урок 7 курса «Английский A1» проходят пять групп,
каждая в свою дату. Одна `Lesson` → пять `Session`. Слияние сущностей потребовало бы
копировать тему и материалы в каждое занятие — и рассинхронизировать их при правке
программы.

**`LessonId` опционален, потому что не всякое занятие соответствует программе:**

- пробное занятие для потенциального ученика,
- отработка пропуска,
- консультация перед экзаменом,
- перенос, на котором разбирали задолженности группы.

Обязательный `LessonId` заставил бы заводить фиктивные уроки «Консультация» в программе
каждого курса.

**Тема занятия может отличаться от темы урока.** Поэтому у `Session` есть собственное поле
`Topic` — переопределение. Пусто → берётся `Lesson.Title`.

**Границы модулей совпадают с границами ответственности.** Программу ведёт методист
([[Curriculum]]), расписание — менеджер ([[Scheduling]]). Разные права, разные экраны,
разная частота изменений.

## Последствия

**Положительные**

- Правка программы не задевает проведённые занятия
- Одна программа обслуживает любое число групп
- Занятия вне программы возможны без искажения курса
- Прогресс группы вычислим: сколько уроков программы уже пройдено

**Отрицательные / принимаемые**

- При отображении занятия нужен join через модули: `Session` → `Lesson` → материалы.
  Кросс-модульный вызов через Contracts, не FK
- Пользователи в разговоре скажут «урок» про оба понятия. UI обязан различать явно:
  «Урок 7 · Past Simple» в программе, «Занятие 12 марта, 18:00» в расписании
- Удаление урока программы, на который ссылаются проведённые занятия, — запрещено
  (только архивация): иначе потеряется история

**Следствия для реализации**

- `Session.LessonId` — nullable, без FK (разные модули)
- `Session.Topic` — переопределение темы
- Материалы урока показываются на карточке занятия через запрос к [[Curriculum]]
- Прогресс группы = количество `Session` со статусом `Held` и непустым `LessonId`
