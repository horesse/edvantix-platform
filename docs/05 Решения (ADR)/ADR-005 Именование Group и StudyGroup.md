# ADR-005 Именование Group и StudyGroup

← [[Edvantix]]

**Статус:** принято · 2026-08-09

## Контекст

Требование задачи называет учебные группы просто «Группы». В [[Identity]] **уже существует**
`Group` (`Identity/Domain/Group.cs`) — группа пользователей для массового назначения ролей,
со связанными `GroupRole` и `UserGroup`, полным набором срезов (`CreateGroup`, `GetGroups`,
`AddUsersToGroup`, `RemoveUserFromGroup`, …) и UI (`dashboard/pages/identity/groups.tsx`).

Два разных понятия претендуют на одно слово. Если это не решить до написания кода,
получим `Group`, `GroupEntity`, `StudentGroup` и `Groups2` вперемешку.

Варианты:

1. Учебная группа = `StudyGroup`, `Identity.Group` не трогаем.
2. Переименовать `Identity.Group` → `AccessGroup`, учебную назвать `Group`.
3. Учебная группа = `Cohort` или `Class`.

## Решение

**Вариант 1.**

| | Identity | Учебная |
|---|---|---|
| Класс | `Group` | `StudyGroup` |
| Модуль | [[Identity]] | [[StudyGroups]] |
| Схема БД | `identity.groups` | `study_groups.study_groups` |
| Права | `Permissions.Groups.*` | `Permissions.StudyGroups.*` |
| Маршрут | `/api/v1/groups` | `/api/v1/study-groups` |
| UI (ru) | «Группы доступа» | «Группы» |
| UI (en) | Access Groups | Groups |

## Обоснование

**Против варианта 2:** переименование `Identity.Group` — миграция таблиц, правка
`GroupRole`/`UserGroup`, всех срезов, прав, фронтенда и тестов. Ради того, чтобы имя класса
совпало со словом в меню. Риск непропорционален выгоде, и Identity — модуль с широким
радиусом поражения.

**Против варианта 3:** `Cohort` — жаргон, непривычный для школ. `Class` конфликтует с
ключевым словом C#, а в русском «класс» вызывает школьные ассоциации, которых у языковых
и IT-школ нет.

**За вариант 1:** `StudyGroup` однозначен и в коде, и в разговоре. Разница между кодом
(`StudyGroup`) и интерфейсом («Группы») допустима — пользователь никогда не видит имён
классов, а разработчик всегда работает с однозначным идентификатором.

`Identity.Group` в русском UI становится «Группами доступа», что точнее описывает его
назначение и без учебных групп.

## Последствия

**Положительные**

- Ноль изменений в существующем коде Identity
- Однозначность в коде: `StudyGroup` ни с чем не спутать
- Пользователь видит привычное слово

**Отрицательные / принимаемые**

- Расхождение кода и UI: класс `StudyGroup`, надпись «Группы».
  Смягчение — [[Глоссарий]] и таблица выше
- Импорт двух `Group` в одном файле требует алиаса. Возникнет редко:
  модули общаются через Contracts, где типы уже разведены пространствами имён
- Правка UI Identity: «Groups» → «Группы доступа»

## Правило для код-ревью

В коде слово `Group` без уточнения — **всегда** группа доступа из Identity.
Учебная — **всегда** `StudyGroup`. Названия вроде `GroupService`, `GroupDto`,
`groupId` в предметных модулях — повод для замечания на ревью.

Исключение — уже принятые составные имена внутри модуля [[StudyGroups]]:
`GroupEnrollment`, `GroupTeacher`, `GroupFormat`. Внутри модуля контекст однозначен,
и `StudyGroupEnrollment` избыточен.
