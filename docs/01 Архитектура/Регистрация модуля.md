# Регистрация модуля

← [[Edvantix]] · [[Карта модулей]]

> [!danger] Четыре места
> Пропущенный маркер Mediator не роняет сборку — обработчики просто не находятся, а эндпоинт
> отвечает 500 в рантайме. Проверяйте по чек-листу.

## Чек-лист

### 1. Атрибут сборки

В `SchedulingModule.cs` (или `AssemblyInfo.cs` — в проекте встречаются оба варианта):

```csharp
[assembly: FshModule(typeof(FSH.Modules.Scheduling.SchedulingModule), 620)]
```

Порядок — из таблицы в [[Карта модулей]].

### 2. `src/Host/Edvantix.Api/Program.cs` → `o.Assemblies`

**Два маркера на модуль** — Contracts и runtime:

```csharp
o.Assemblies = [
    // …
    typeof(FSH.Modules.Scheduling.Contracts.SchedulingContractsMarker),
    typeof(FSH.Modules.Scheduling.SchedulingModule)];
```

### 3. `src/Host/Edvantix.Api/Program.cs` → `moduleAssemblies`

```csharp
var moduleAssemblies = new Assembly[]
{
    // …
    typeof(SchedulingModule).Assembly,
};
```

### 4. `src/Host/Edvantix.DbMigrator/Program.cs`

**Та же пара** — иначе миграции и сиды модуля не применятся.

### Дополнительно

- `src/Edvantix.slnx` — папка `/Modules/Scheduling/` с обоими проектами
- `src/Host/Edvantix.Migrations.PostgreSQL/Scheduling/` — папка под миграции
- `src/Tests/Scheduling.Tests/` — проект тестов (+ в `.slnx`)
- `.agents/rules/modules/scheduling.md` — правила модуля для ИИ-инструментов
- `docs/02 Модули/Scheduling.md` — эта документация

## Реализация `IModule`

```csharp
public sealed class SchedulingModule : IModule
{
    public void ConfigureServices(IServiceCollection services, IConfiguration configuration)
    {
        services.AddDbContext<SchedulingDbContext>(/* … */);
        services.AddScoped<ISessionConflictChecker, SessionConflictChecker>();
        PermissionConstants.Register(SchedulingPermissions.All);
    }

    public void MapEndpoints(IEndpointRouteBuilder app)
    {
        var group = app.MapGroup("/api/v1/scheduling").WithTags("Scheduling");
        group.MapCreateSessionEndpoint();
        // …
    }
}
```

Права регистрируются в `ConfigureServices` через `PermissionConstants.Register` —
центрального списка нет, каждый модуль вносит свои. См. [[Модель прав доступа]].

## Проверка

```bash
dotnet build src/Edvantix.slnx
```

```bash
dotnet test src/Tests/Architecture.Tests
```

`Architecture.Tests` проверяет: границы модулей, `sealed` у обработчиков, наличие
валидаторов у команд и пагинированных запросов.

Затем убедиться, что эндпоинты видны в Scalar: <https://localhost:7030/scalar>.
